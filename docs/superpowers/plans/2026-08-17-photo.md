# Défi photo — plan d'implémentation

> **Pour les agents :** COMPÉTENCE REQUISE — utiliser `superpowers:subagent-driven-development`
> pour exécuter ce plan tâche par tâche. Les étapes sont des cases à cocher.

**But :** ajouter un troisième défi. L'application nomme un objet, l'alarme ne se
tait qu'une fois une photo de cet objet prise en direct et acceptée par un juge.

**Architecture :** noyau de décision pur (catalogue, jugement, progression), une
interface `JugePhoto` à deux implémentations — embarquée par ML Kit, distante et
optionnelle —, et un `PhotoChallenge` qui n'est que du câblage.

**Pile :** Kotlin, Compose, CameraX 1.3.4, ML Kit `image-labeling` 17.0.9
(modèle embarqué), DataStore, Room.

**Spec :** `docs/superpowers/specs/2026-08-17-photo-design.md`

## Contraintes globales

- `minSdk 28`, `targetSdk 35`. Code, commentaires, KDoc et interface en français ;
  commits et noms d'API en anglais.
- Toute décision testable vit dans une classe **sans import `android.*`**, couverte
  par des tests unitaires. Les composants Android ne font que du câblage.
- **Aucune photo n'est écrite sur le disque**, dans aucun mode.
- **Aucun chemin ne doit rendre l'alarme impossible à arrêter.** Toute exception
  vaut refus, jamais plantage.
- Un `Text` sans couleur explicite peut sortir illisible : le thème fournit
  `LocalContentColor` globalement, imiter les composables voisins.
- Les dépendances CameraX et ML Kit sont **déjà ajoutées et vérifiées** (`d1cb6b0`).

class CatalogueObjetsTest {
    @Test fun `le tirage rend le nombre demande`() {
        assertEquals(3, CatalogueObjets.tirer(3, emptySet(), Random(1)).size)
    }

    @Test fun `le tirage ne repete jamais un objet`() {
        val tires = CatalogueObjets.tirer(5, emptySet(), Random(2))
        assertEquals(5, tires.map { it.id }.toSet().size)
    }

    @Test fun `le tirage evite les objets exclus`() {
        val exclus = CatalogueObjets.tous.take(3).map { it.id }.toSet()
        val tires = CatalogueObjets.tirer(3, exclus, Random(3))
        assertTrue(tires.none { it.id in exclus })
    }

    @Test fun `demander plus d objets que le catalogue n en a ne boucle pas`() {
        // Sans borne, une boucle de tirage sans remise tournerait indéfiniment
        // et l'alarme resterait bloquée sur un écran vide, sirène en marche.
        val tires = CatalogueObjets.tirer(CatalogueObjets.tous.size + 5, emptySet(), Random(4))
        assertEquals(CatalogueObjets.tous.size, tires.size)
    }

    @Test fun `exclure tout le catalogue rend quand meme un objet`() {
        // Cas réel : la difficulté demande trois objets et les trois du réveil
        // précédent sont exclus alors que le catalogue est petit. Mieux vaut
        // répéter un objet que ne rien afficher.
        val tous = CatalogueObjets.tous.map { it.id }.toSet()
        assertTrue(CatalogueObjets.tirer(1, tous, Random(5)).isNotEmpty())
    }

    @Test fun `chaque objet porte au moins une etiquette et un nom francais`() {
        CatalogueObjets.tous.forEach {
            assertTrue(it.nom.isNotBlank())
            assertTrue(it.etiquettes.isNotEmpty())
        }
    }

    @Test fun `les identifiants sont uniques`() {
        assertEquals(CatalogueObjets.tous.size, CatalogueObjets.tous.map { it.id }.toSet().size)
    }

    @Test fun `les etiquettes sont normalisees en minuscules`() {
        // Le jugement compare sans tenir compte de la casse ; une étiquette
        // écrite « Mug » dans le catalogue et « mug » par le modèle doit
        // correspondre. On normalise à la source plutôt qu'à chaque comparaison.
        CatalogueObjets.tous.forEach { objet ->
            objet.etiquettes.forEach { assertEquals(it.lowercase(), it) }
        }
    }
}

class JugementPhotoTest {
    private val tasse = ObjetPhoto("tasse", "Tasse", setOf("mug", "cup"))

    @Test fun `une etiquette attendue au dessus du seuil accepte`() {
        assertTrue(JugementPhoto.accepte(tasse, listOf(EtiquetteReconnue("Mug", 0.9f))))
    }

    @Test fun `la comparaison ignore la casse`() {
        assertTrue(JugementPhoto.accepte(tasse, listOf(EtiquetteReconnue("MUG", 0.9f))))
    }

    @Test fun `un synonyme du catalogue accepte aussi`() {
        assertTrue(JugementPhoto.accepte(tasse, listOf(EtiquetteReconnue("cup", 0.8f))))
    }

    @Test fun `une etiquette attendue sous le seuil refuse`() {
        assertFalse(JugementPhoto.accepte(tasse, listOf(EtiquetteReconnue("mug", 0.2f))))
    }

    @Test fun `une etiquette exactement au seuil accepte`() {
        // Frontière explicite : sans ce test, passer de >= à > changerait le
        // comportement sans faire rougir quoi que ce soit.
        assertTrue(JugementPhoto.accepte(tasse, listOf(EtiquetteReconnue("mug", 0.55f))))
    }

    @Test fun `un autre objet tres reconnaissable refuse`() {
        assertFalse(JugementPhoto.accepte(tasse, listOf(EtiquetteReconnue("shoe", 0.99f))))
    }

    @Test fun `aucune etiquette refuse`() {
        assertFalse(JugementPhoto.accepte(tasse, emptyList()))
    }

    @Test fun `le bon objet compte meme noye parmi d autres etiquettes`() {
        // Une photo de bureau rend beaucoup d'étiquettes ; exiger que la bonne
        // arrive en tête rejetterait des photos parfaitement valables.
        val etiquettes = listOf(
            EtiquetteReconnue("table", 0.95f),
            EtiquetteReconnue("wood", 0.9f),
            EtiquetteReconnue("mug", 0.7f),

        assertTrue(JugementPhoto.accepte(tasse, etiquettes))

class PhotoChallengeEtatTest {
    private val a = ObjetPhoto("a", "A", setOf("a"))
    private val b = ObjetPhoto("b", "B", setOf("b"))

    @Test fun `le premier objet est propose d emblee`() {
        assertEquals(a, PhotoChallengeEtat(listOf(a, b)).objetCourant.value)
    }

    @Test fun `un refus ne fait pas avancer et compte un essai`() {
        val etat = PhotoChallengeEtat(listOf(a, b))
        assertFalse(etat.soumettre(accepte = false))
        assertEquals(a, etat.objetCourant.value)
        assertEquals(1, etat.essais.value)
        assertFalse(etat.isSolved.value)
    }

    @Test fun `un accord passe a l objet suivant sans compter d essai rate`() {
        val etat = PhotoChallengeEtat(listOf(a, b))
        assertTrue(etat.soumettre(accepte = true))
        assertEquals(b, etat.objetCourant.value)
        assertEquals(0, etat.essais.value)
    }

    @Test fun `valider tous les objets resout le defi`() {
        val etat = PhotoChallengeEtat(listOf(a, b))
        etat.soumettre(accepte = true)
        etat.soumettre(accepte = true)
        assertTrue(etat.isSolved.value)
        assertNull(etat.objetCourant.value)
    }

    @Test fun `une fois resolu plus rien ne change`() {
        val etat = PhotoChallengeEtat(listOf(a))
        etat.soumettre(accepte = true)
        assertFalse(etat.soumettre(accepte = true))
        assertEquals(1, etat.progression.value.first)
    }

    @Test fun `une liste vide est resolue et n affiche aucun objet`() {
        // Cas de repli : si le catalogue rendait une liste vide, le défi doit
        // se résoudre plutôt que bloquer l'utilisateur devant une sirène.
        val etat = PhotoChallengeEtat(emptyList())
        assertTrue(etat.isSolved.value)
        assertNull(etat.objetCourant.value)
    }

    @Test fun `la progression suit les objets valides`() {
        val etat = PhotoChallengeEtat(listOf(a, b))
        assertEquals(0 to 2, etat.progression.value)
        etat.soumettre(accepte = true)
        assertEquals(1 to 2, etat.progression.value)
    }
}

- [ ] **Étape 1 : implémenter**

  fuit.
- La conversion `Task` → `suspend` passe par `kotlinx.coroutines.tasks.await` si
  la dépendance est présente, sinon par `suspendCancellableCoroutine` — vérifier
  laquelle est disponible plutôt que de supposer.

décision est déjà couverte par `JugementPhotoTest`. C'est la règle du projet, ne
pas inventer de test instrumenté.

### Tâche 6 : Le défi

**Fichiers :**

**Interfaces :**
- Consomme : tout ce qui précède.
- Produit : `class PhotoChallenge(context, difficulty, iaDistanteActive, cleApi, onInteraction, onRenoncer) : Challenge`,
  plus `companion object { fun nombrePour(difficulty: Difficulty): Int }` et
  `val camerasDisponibles: Boolean`.

- [ ] **Étape 1 : la permission**

Ajouter `<uses-permission android:name="android.permission.CAMERA" />` au manifeste.

- [ ] **Étape 2 : implémenter le défi**

Prendre `PompesChallenge` comme modèle — même structure, mêmes conventions.

- `nombrePour` : 1 en facile, 2 en moyen, 3 en difficile.
- Aperçu CameraX (`PreviewView` dans un `AndroidView`) **dans l'écran d'alarme**,
  jamais par un intent vers l'application appareil photo : en sortir ouvrirait un
  chemin vers les réglages du téléphone pendant que l'alarme sonne.
- `ImageCapture` en mémoire (`takePicture` avec le rappel en mémoire), converti en
  `Bitmap`. **Jamais de fichier.**
- Enchaînement des juges : l'embarqué d'abord ; s'il refuse **et** que le mode
  distant est actif avec une clé non vide, demander au distant. Un accord de
  l'embarqué n'est jamais soumis au distant — c'est gratuit et instantané, il n'y
  a aucune raison de payer pour le contredire.
- Chaque déclenchement appelle `onInteraction()`, comme une répétition de pompes.
- Bouton « Je ne peux pas — appui long », `combinedClickable` avec `onLongClick`,
  exactement comme `PompesChallenge`.
- Libération : `DisposableEffect` qui ferme le juge embarqué et libère la caméra.
- `camerasDisponibles` : `packageManager.hasSystemFeature(FEATURE_CAMERA_ANY)` **et**
  juge embarqué disponible.
- Pendant l'attente d'un verdict, l'écran montre qu'il travaille et **empêche un
  second déclenchement**, sans quoi deux verdicts pourraient se croiser.
